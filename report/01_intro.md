# 1 引言

## 1.1 研究背景

视觉-语言预训练模型（VLM）已经成为图文检索、零样本分类、多模态问答等任务的基础设施。以 CLIP 为代表的对比学习模型，通过大规模图文对的 InfoNCE 目标，把图像与文本映射到同一嵌入空间，并用余弦相似度完成匹配[1,3,4]。这种“双塔 + 点积”的结构简单、可扩展，却有一个被反复观察到的弱点：模型对**组合结构**不敏感。面对“狗追猫”与“猫追狗”、“红色杯子在蓝色盘子左边”与“蓝色杯子在红色盘子左边”这类只改变词序或句法角色的句子，CLIP 往往给出几乎相同的相似度[5,6]。

Winoground[5] 用 400 组精心构造的最小对立对，把这一问题量化：一组两张图、两句 caption，四个图文组合中只有两个是正确的。CLIP ViT-B/32 在该数据集上的 group 准确率通常只有个位数到十几个百分点。ARO[6] 进一步把失败拆成 attribution（属性错配）、relation（关系方向）、order（词序）三类，并指出模型“像词袋一样”依赖名词共现。SugarCrepe[7] 则指出早期基准可以被“只改一个词”的浅层线索 hack，提出用更自然的负例重新评测；SugarCrepe++[8] 进一步区分语义改变与词法改变，要求模型同时对“换词”和“换序”敏感。

这些基准共同说明：**对比学习目标只约束“整句与整图是否匹配”，没有显式约束句法结构**。当负例在词袋层面与正例高度重叠时，模型缺少可用的监督信号去区分词序。于是，研究社区从两个方向改进：一是数据侧，引入硬负例、合成组合数据或重新加权[6,9]；二是模型侧，加入循环一致性、区域对齐、计数模块、轻量适配器或蒸馏[9,10,12]。但在此之前，必须回答一个更基础的问题：**CLIP 到底缺的是信息，还是读法？**

## 1.2 问题陈述

本项目把“组合性失败”拆成三个可检验的问题：

- **RQ1（词序敏感性）**：在词袋完全相同的条件下，CLIP 能否仅凭词序/句法角色区分正确描述与错误描述？不同变换（主宾交换、名词交换、形容词交换、全词打乱）的敏感度是否一致？
- **RQ2（失败模式）**：在 Winoground、ARO、SugarCrepe++ 上，错误集中在哪些语言类型？是“完全不会”还是“差一点”（近失手）？不同基准的失败结构是否一致？
- **RQ3（改进方向）**：如果信息存在于表征中，轻量适配器/蒸馏能否以低成本把信息“读出来”；如果信息不存在，硬负例训练是否必要？该问题由团队 E1–E4 实验回答，本文第 3–4 章提供机制与诊断依据。

## 1.3 本文贡献（成员 1 部分）

1. **可复现的组合探针（0-B）**：构造 5 类保持词袋不变的变换，在 Flickr30k test 上测 CLIP 的词序敏感度，并加入 unrelated 对照校准任务难度。所有样本、负例与分数落盘，可逐条审计。
2. **失败模式分类（0-C）**：把 E0 的逐样本错误按 order / attribute / relation / object / add 分桶，统计错误率、平均 margin、近失手比例与“自信错误”比例，输出可直接引用的典型错误。
3. **E0 基线**：在 Winoground、ARO（VG-Relation / VG-Attribution / Flickr-Order）、SugarCrepe++ 上给出 ViT-B-32/laion2b 的统一评测，附 bootstrap 95% CI 与逐样本结果。
4. **工程与复现**：修正 SugarCrepe++ 负例字段、加入图片/文本去重与宏平均、本地化 Winoground 加载，编写数据来源与决策日志，保证队友在无 gated 权限时也能复现。

## 1.4 报告结构

第 2 章回顾组合性评测与改进方法；第 3 章给出 0-A/0-B 的机制分析；第 4 章给出 E0 结果与 0-C 失败诊断；第 5–7 章分别由成员 2/3 撰写数据与训练、改进方法、结论与展望。第 8 章为统筹说明与附录。
