# 7 结论与展望

> 本章基于正式 GPU 结果定稿。E0–E4b 的共同比较使用 2/4 ARO + 2/3 SugarCrepe；
> E0–E4b 的预注册主指标使用 A2 4/3 全量。两套口径不混算。

## 7.1 主要结论

1. **E1/E2/E2a 在共同 2/2 上高于 E0**：ARO VG macro 从 E0 的 54.416% 提升到
   E1/E2/E2a 的 57.4–58.0%；SugarCrepe macro 从 73.897% 提升到 77.1–77.4%。
   E0 已改用 A2 4/3 重跑结果，ARO 使用与 E1–E4b 相同的 VG-crop 协议，因此这次
   比较比早期 A1 归档更严格。但在 4/3 全量上，E0 的 Flickr-Order 为 40.680%，
   高于 E1/E2/E2a 的 29.5–30.4%，所以 E0 的 ARO macro 反而更高；三者的 4/3
   组合优势主要来自 Sugar。共同 2/2 的提升不能外推到所有子集。
2. **E2 是 E1/E2/E2a 中的最佳选模结果**（4/3 selection score 62.5683%），但
   三者差别很小，且 E1/E2 同时改变来源与覆盖量，不能单独归因于负例来源。
3. **E3 在预注册的 A2 4/3 主指标上达标**：ARO 48.195%、Sugar 79.404%、组合
   均值 **63.799%**；相对 E0（45.486% / 77.539% / 61.512%）为 ARO **+2.709pp**、
   Sugar **+1.865pp**、组合 **+2.287pp**，达到 ≥ +2.0pp 的主标准；全量配对 CI
   均排除 0。COCO t2i 41.029% 相对 E0 的 38.794% **+2.235pp**，没有遗忘。
4. **但 E3 的收益是 order 子集驱动的**：COCO-Order 32.431%→39.244%，
   Flickr-Order 40.680%→44.740%；VG-Relation 50.077%→49.463%，
   VG-Attribution 58.755%→59.333%，基本持平。共同 2/2 上 E3 与 E0 的 ARO 只差
   **−0.018pp**（CI 跨 0），Sugar 高 **+2.707pp**（显著）。因此应写成
   “**order/COCO 收益 + VG 代价**”，不能宣称所有组合子集全面提升。
5. **E3 相对 E-best（E2）的组合均值仍高 +1.231pp**，满足“下降 ≤0.5pp”的附加
   标准；但 Sugar 单项低 0.910pp（CI 跨 0），且 E2 没有同批次 COCO，无法验证
   “E3 的 COCO 遗忘比 E-best 更小”这一条。
6. **E4b 与 E2 接近，但没有明显优势**：4/3 组合均值 62.810% vs E2 62.568%
   （+0.242pp），相对 E0 为 +1.298pp；共同 2/2 上 ARO −0.450pp、Sugar
   −1.085pp；Flickr30k t2i 71.44%（比 E2 低 1.54pp），i2t 88.50%（比 E2 高
   1.00pp）。锁图像塔没有表现出稳定的组合增益。
7. **预注册主标准整体判定**：E3 相对 E0 的 4/3 组合增益 +2.287pp、COCO 不降反
   升，**主标准成立**；E3 相对 E-best 的组合指标不降，**附加标准也成立**；但
   “COCO 遗忘比 E-best 更小”因 E2 缺 COCO 而**未验证**。结论应表述为
   “在冻结 4/3 指标上成立、机制集中在 order 子集”，而不是“蒸馏全面提升组合
   推理”。

## 7.2 失败模式与解释

ARO 的主要错误是关系方向反转、属性绑定错位和 order 子集的短语顺序打乱；
SugarCrepe 的主要错误是近义/关系替换、对象/属性 swap 和 add 的额外对象插入。
正式失败案例见 `report/results/failure_cases.md`（E3，ARO 15 条 + Sugar 15 条）。

这些样本说明模型仍依赖表面词序和显著对象，而不是稳定的关系/属性结构；但 30 条
是按 margin 选出的边界样本，不能当作错误比例估计。结合 0-C 的诊断，当前证据更
支持“E3 改善了 order 敏感性，但没有解决细粒度关系/属性绑定”，而不是单一的数据
噪声解释。

## 7.3 局限

1. 单训练 seed；无第二 seed，不能宣称稳定性。
2. 共同 2/2 与 A2 4/3 是两套口径；E3 在 2/2 的 VG 子集上与 E0 持平，在 4/3
   上因 order 子集提升而胜出，任何单表结论都必须标注口径。
3. E0 有 A1 归档（53.987/74.314）和 A2 4/3（54.416/73.897）两个版本；主表用
   A2 版本，旧值只作历史对照。
4. E4b 的 Sugar 在 A2 4/3 与旧 `evals-mm` 2 家族之间差 0.439pp；主表统一采用
   A2 4/3。
5. **E2 没有同批次 COCO**，预注册的“E3 的 COCO 遗忘比 E-best 更小”无法验证；
   E1/E2/E2a 的 COCO 也没有在同一批次评测。
6. E2a 与 E2 数量不匹配；E1 与 E2 来源/覆盖同时变化。
7. Flickr30k/Winoground 部分使用公开镜像；官方数据复核未完全闭合。
8. Winoground 只有 400 对，统计功效有限；CI 跨 0 的提升不能写成结论。
9. 训练监控不是 formal benchmark。
10. 预训练数据污染、模型偏差、LLM 生成非确定性未完全排除。

## 7.4 展望

- **补 E2 的 COCO 4/3 评测**，使“E3 的 COCO 遗忘是否小于 E-best”可以验证；
  这是当前最重要的单个缺口。
- 补 E1/E2/E2a 的同批次 COCO，形成完整的 6 模型 COCO 表。
- 补第二个训练 seed、matched-size 负例对照和更多基座（如 ViT-B/16 SigLIP）。
- 用官方 Flickr30k/Winoground 数据复核，并补 ARO COCO-Order 与 SugarCrepe
  `add` 的独立分析。
- 针对 E3 的“order 收益、VG 代价”做消融：分别控制蒸馏温度、order 子集采样
  比例和 VG 数据权重，验证是否能同时保住 VG 关系/属性。
- 把 E-best 封装为 `ImageTextEncoder` 服务，接入 Mnemo 的图像记忆检索。
